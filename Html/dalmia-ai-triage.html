Dalmia AI Triage & Classification Engine

A production-grade AI support platform that automatically triages and classifies incoming application-support tickets. Built on a Model Context Protocol (MCP) architecture with a config-driven LangGraph pipeline and FastAPI backend, it routes each ticket to the right team in seconds and escalates low-confidence cases to humans.

Key Achievements

  • Seconds-to-classify: Replaces manual ticket triage with an automated preprocess → classify → parse pipeline that returns a routed category with a confidence score.
  • Confidence-based routing: High-confidence tickets (≥0.85) auto-route to the correct team; medium/low-confidence tickets are flagged for human review, eliminating silent misroutes.
  • Multi-provider, zero lock-in: Pluggable LLM factory supports OpenAI, Anthropic Claude, and Google Gemini, all selectable at request time without code changes.
  • Config-driven: Categories, colors, routing targets, models, and thresholds all live in config.yaml — tuning classification requires no redeploy.
  • Vision-ready: Accepts screenshot uploads (base64 or multipart) so users can attach error screens for richer classification.

Technical Architecture

The system is Module 1 of a larger AI-Driven Application Support Platform and is built around a clean separation of secrets, configuration, and logic:

  • Orchestration: LangGraph pipeline (preprocess → classify → parse) defined in classification/graph.py.
  • Backend: FastAPI server exposing classification, validation, and config endpoints with interactive Swagger docs.
  • LLM Factory: llm_factory.py reads config.yaml and instantiates the chosen provider/model at runtime.
  • Config Layer: .env holds secrets (API keys, host/port, CORS); config.yaml holds models, categories, colors, and confidence thresholds; config.py unifies them into a single settings object.
  • Schemas: Pydantic request/response models in models.py for strict validation.
  • Prompts: Classification logic and templates centralized in classification/prompts.py.

API Endpoints

  • POST /classify: Classify a ticket from a JSON body.
  • POST /classify-upload: Classify with a file/screenshot upload (multipart).
  • POST /validate-key: Validate an API key to enable chat.
  • GET /providers: List available LLM providers and models from config.
  • GET /categories: Classification categories with badge colors and routing targets.
  • GET /config: Non-sensitive configuration (no API keys exposed).
  • GET /health: Health check. GET /docs: Interactive Swagger UI.

Classification Flow

  • 1. Provider selection: Frontend loads providers from /providers and pre-detects which keys are configured in .env.
  • 2. Key validation: A user-entered key (or the .env fallback) is validated via /validate-key before chat is enabled.
  • 3. Classify: The ticket message (plus an optional screenshot) is sent to /classify with the chosen provider and model.
  • 4. Route & display: The returned category, confidence, and routing target are rendered as a colored badge pulled from /categories.

Technology Stack

  • Orchestration: LangGraph
  • Backend: FastAPI (Python 3.11)
  • LLM Providers: OpenAI, Anthropic Claude, Google Gemini (Gemini 2.5 Flash default)
  • Architecture: Model Context Protocol (MCP)
  • Validation: Pydantic
  • Config: YAML + dotenv unified settings
  • Docs: Swagger / OpenAPI

Business Impact

  • Automated ticket triage that routes to the correct team in seconds instead of manual review
  • Confidence thresholds prevent silent misroutes by escalating uncertain cases to humans
  • Config-driven categories and routing let support leads tune behavior without engineering
  • Provider-agnostic design avoids vendor lock-in and enables cost/latency tuning per model
